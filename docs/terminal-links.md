# Links in terminal output

Web addresses and existing Markdown note paths are clickable wherever xterm renders text, including agent responses and side terminals. HTTP and HTTPS addresses use Electron's system-browser opener. Other external schemes are ignored, including OSC 8 terminal hyperlinks.

Note paths resolve relative to the active vault, regardless of the terminal's working directory. Relative paths, absolute paths inside the vault, `/` and `\` separators, spaces and Unicode are supported. Backticks, quotes, parentheses and Markdown link destinations can delimit a path. For unquoted space-containing paths, the provider chooses the first candidate that matches an existing indexed note, excluding preceding prose. It does not search by note basename or create missing files.

Suffixes `:42` and `:42:8` mean one-based line and column. The editor opens in source mode for these locations and clamps a position beyond the end of a note. Obsidian's normal Cmd/Ctrl modifier behavior selects a new tab or split. Ordinary clicks open through the normal navigable editor leaf.

When OpenCode enables terminal mouse reporting, ordinary clicks remain owned by its TUI. Hold Cmd/Ctrl while clicking a link to activate it. Dragging or an existing terminal selection never activates a link. Modifier activation on a hovered link consumes its mouse press/release before they reach OpenCode; non-link input keeps its normal behavior.

Paths must resolve lexically inside the active vault and refer to an indexed Markdown file. Activation additionally checks canonical filesystem paths, rejecting symlinks that escape the vault. There is no outside-file fallback. Under WSL, Windows drive paths map to `/mnt/<drive>` only when the active vault uses that mount. `\\wsl.localhost\<distro>` and `\\wsl$\<distro>` aliases require the active `WSL_DISTRO_NAME` to match. Custom WSL automount locations are not inferred.

Wrapped xterm lines use cell coordinates, including wide characters, surrogate pairs, combining characters and wide-character wrap padding. Ordinary hard line breaks are not joined. When the TUI enables mouse reporting, consistently indented paragraphs and bullet continuations can also form a note path across rows: OpenCode performs this layout itself without xterm's wrap flag. These continuations require an exact indexed Markdown path, support mixed word and mid-word breaks within the same path (including a split `.md` extension), and retain all vault-containment checks. Detection is bounded to 128 native wrapped rows, 16,384 UTF-16 units per logical line, and 4,096 units per delimiter-bounded path phrase; TUI continuation starts are searched within eight rows, with at most 128 combinations of spaces at row boundaries. Filesystem canonicalization runs only on activation, never on hover; hover checks use indexed vault lookups.

Bordered TUI tables also support note paths split within one cell. The provider removes cell padding, matches physical border columns, and resolves the complete reconstructed cell as an exact indexed note. This supports punctuation in filenames, repeated `.md` suffixes, and line/column references. Continuation rows must leave the other cells blank; separators, changed column positions, blank path cells, and new numbered records stop reconstruction. Detection is limited to eight rows, 16 columns, and 4,096 UTF-16 units per candidate. Table borders and neighboring cells are excluded from underlines and click targets; a missing or outside path never falls back to a basename fragment.

Plain HTTP(S) URLs can also span indented TUI rows, including bullets and code blocks. The provider joins consecutive URL tokens without inserting spaces and opens the complete address from any covered row. It recognizes a filled row or a break at a URL separator, and stops at blank rows, changed indentation, another URL, or prose containing spaces. Short completed URLs remain independent. Detection is limited to 32 rows and 4,096 UTF-16 units; a recognized continuation beyond either limit suppresses the partial first-row target. This is a layout heuristic: a full-width URL followed immediately by a single-word row can be ambiguous. Wrapped table URLs and arbitrary manually inserted newlines are not reconstructed. Hovering any TUI fragment underlines all fragments of the complete link together. Each underline and click target uses its row's actual text cells, excluding indentation and right padding; every row still opens the complete target. The decoration uses non-interactive overlays that clear on leave, buffer changes, scroll, resize, or disposal. Embedded OSC 8 targets retain priority.

xterm 5.5 does not expose OSC 8 cell URLs in its public API. The isolated `xtermOsc8.ts` adapter reads its cell URL id and link registry to verify the current target instead of trusting cached hover state. It fails closed when URL metadata exists but the registry is unavailable; this seam must be checked when upgrading xterm.
